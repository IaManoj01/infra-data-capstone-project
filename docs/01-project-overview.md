# Solar Farm Infrastructure and Data Analytics Platform

## 1. Project Overview

### 1.1 Introduction

The Solar Farm Infrastructure and Data Analytics Platform is an end-to-end data engineering and application development project designed to simulate, collect, process, store, and analyze solar power generation data.

The platform combines a Python-based data simulator, a Spring Boot backend, a React frontend, AWS cloud infrastructure, Snowflake data ingestion, and Power BI dashboards.

The objective is to demonstrate how data generated by solar farm equipment can be transformed into useful operational information through an automated data pipeline.

### 1.2 Problem Statement

Solar power facilities generate operational data from multiple inverters and environmental monitoring devices. This data can include power generation, irradiance, temperature, voltage, and equipment status.

Without a structured data pipeline, it can be difficult to:

- Collect and organize generation and weather observations.
- Monitor generation across multiple sites and inverters.
- Identify abnormal generation readings.
- Track equipment faults and maintenance tickets.
- Transfer operational data into an analytics platform.
- Present meaningful insights through dashboards.

This project addresses these challenges by integrating application services and cloud-based data processing components.

### 1.3 Project Objectives

The primary objectives are:

1. Simulate solar generation and weather observations.
2. Store operational data in a relational database.
3. Provide REST APIs to retrieve and manage solar farm information.
4. Support fault-ticket creation and status management.
5. Automate the extraction and transfer of data to cloud storage.
6. Integrate AWS storage and messaging services with Snowflake ingestion.
7. Build dashboards for monitoring and analyzing solar farm performance.
8. Automate application testing and deployment through GitHub Actions.

### 1.5 High-Level Project Workflow

1. The Python simulator generates solar generation and weather data.
2. Operational records are stored in MySQL.
3. The Spring Boot backend exposes REST APIs to access and manage the records.
4. The ETL process extracts data and transfers files to Amazon S3.
5. AWS messaging and Snowflake ingestion components support downstream data loading.
6. Snowflake stores the analytical data.
7. Power BI connects to the analytical data to present dashboards.
8. GitHub Actions validates code changes and deploys successful changes to the EC2 environment.

### 1.6 Key Project Components

- **Data Simulator:** Generates simulated solar farm operational observations.
- **Backend Service:** Provides APIs for generation, weather, fault tickets, and ETL execution.
- **Frontend Application:** Provides the user interface for interacting with the platform.
- **MySQL Database:** Stores operational application data.
- **AWS Infrastructure:** Hosts the production application and supports cloud data transfer.
- **Snowflake:** Acts as the analytical data warehouse.
- **Power BI:** Presents reports and operational insights.
- **CI/CD Pipeline:** Automates validation and deployment.

### 1.7 Expected Outcomes

The completed platform demonstrates an integrated workflow from simulated operational data to cloud-based analytics. It also demonstrates backend development, frontend integration, relational database usage, containerization, cloud deployment, and automated CI/CD.
